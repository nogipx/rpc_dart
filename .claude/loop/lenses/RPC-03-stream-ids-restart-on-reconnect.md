# RPC-03 — Идентификаторы потоков, переживающие переподключение

Уточняет:    U-18

Форма:       менеджер идентификаторов начинает нумерацию заново, пока живы
             операции, выданные до разрыва.
Детектор:    `RpcStreamIdManager`, `resumeAfter`, `lastIssuedId`,
             `RpcChannelTransport.resumeStreamIdsAfter`, `lastIssuedStreamId`.
Спрашивать:  может ли очистка мёртвой операции закрыть живую с тем же
             идентификатором?
Ломается:    потеря данных на живом вызове.
Улика:       очистка мёртвого вызова полузакрывала ЖИВОЙ; оба очевидных фикса
             не сработали.
Статус:      подтверждена (websocket, http2)
